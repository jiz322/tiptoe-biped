  • Git-tag the current state of RL/ and control/ (e.g. pre-replant-20260817) so every fitted number is attributable to a code state.
  • Verify the driver velocity-decode fix is deployed (the June sysid data carried a ×1.136 decode error). Spin a joint at a known slow rate against the encoder position derivative; the two must agree to <2%. If this fails, stop — every measurement today inherits the error.
  • Reply-collision guard: superseded 08-16 (BASELINE_RUNBOOK Phase D) — each motor now replies on its own host id and CAN2SPI_PACING_S = 0.0 is the validated config. Check instead that this boot's setup_can0.sh passed its duplicate-reply-id guard (it refuses on duplicates; a swapped-in motor at factory 0xFD would re-create the collisions).
  • Re-dump firmware params for all six motors, not just the two on file — confirm the two knees and both hip pitches match fw_rs01_pitch_knee_20260815.csv, both rolls match the EL05 dump. Per-unit spread in spd_filt_gain / limit_cur matters.
  • Robot on the stand, e-stop tested, spare fuses at hand for the stall tests.
Telemetry ground rules for every phase. (1) Never use torque_fdb as truth — it carries a ~25–35 ms filter plus a 0.15 Nm deadband; use commanded iq × Kt plus external physics (weights, encoder kinematics) instead. (2) Run Isaac Lab scripts from an activated env_isaaclab shell, not conda run (it buffers stdout and you lose live prints). (3) Log raw timestamps on the host for everything; derive nothing on the fly.

Phase 1 — Loop timing on CAN2SPI ~1.5 h

Every number in cfg §12b (action 15 ms, IMU 5–7 ms, joint 15–20 ms, "IMU leads encoder by 10 ms") is CAN2USB-era. The joint path was the CAN-bound one, so the skew may have shrunk or inverted.

M1.1 — Action → torque onset

Procedure  MIT mode, kp=kd=0, command a τff step on one unloaded joint; detect motion onset from the encoder second-difference. Host-timestamp send and onset. N≥50 steps, both directions, all three joint types.

Record  mean, p95, std of send→onset latency per joint type.

Accept  p95 spread <1 control step; otherwise investigate jitter before proceeding.

feeds → dr_action_delay_min/max

M1.2 — IMU vs encoder staleness

Procedure  Excite an event both sensors see simultaneously: oscillate hip_pitch by hand with the torso free so the IMU pitches as the encoder moves. Cross-correlate host-side arrival streams (IMU pitch rate vs encoder velocity) to get the relative lag; get absolute lags by pairing with M1.1's clock.

Record  per-path staleness (ms) and which path leads. Do not assume the old ordering.

feeds → dr_imu_delay_*, dr_joint_delay_* (min = measured floor rounded up; max = floor + 1 step)

M1.3 — Tick health

Procedure  Log 10 min of control-loop timestamps under full 6-motor traffic. Histogram tick duration; count >5 ms outliers and any reply collisions.

Accept  tick 3.6 ms nominal, <0.1% ticks over 10 ms (one control period).

Phase 2 — Velocity filter in the kd path ~2 h

Leading fall candidate. Firmware filters velocity before the MIT-mode kd: RS01 spd_filt_gain=0.1 (heavy), EL05 spd_filt_gain=0.5. Sim damping acts on instantaneous 500 Hz velocity — an unmodeled phase lag exactly where the balance loop needs margin. Both registers are R/W, so we can either model the filter or remove it.

M2.1 — Identify the filter corner

Procedure  kd-only config (kp=0, kd = deployed value, v_des=0). Backdrive the joint sinusoidally (by hand against a metronome, or with a second motor) at ~0.5 / 1 / 2 / 4 / 8 Hz. Log commanded iq and encoder velocity; fit gain and phase of the damping response vs frequency. The phase rolloff gives the EMA's effective corner — this also pins the firmware update rate the gain applies at, which we currently do not know.

Record  corner frequency (Hz) and equivalent 500 Hz-rate EMA alpha, per motor type.

feeds → new spd_filt EMA state in belt_knee_actuator (phase 7)

M2.2 — Firmware A/B: raise the gain instead?

Procedure  Write spd_filt_gain to 0.3 / 0.5 / 1.0 on one RS01; repeat a kp+kd step response at each setting. Look for (a) reduced ring lag, (b) any new velocity-noise chatter in the torque (the filter exists for a reason).

Decide  If a higher gain is clean: fix it in firmware on all four RS01s, and sim needs only the (weaker) residual filter. If chatter appears: keep 0.1 and model it faithfully in sim. Either way the sim and firmware must end today matched.

M2.3 — EL05 position-reference filter

Procedure  EL05 carries loc_ref_filt_gain=0.04 — a very heavy reference filter of unknown scope. Command a position step in MIT mode (kp nominal, kd=0, τff=0) and compare measured rise against ideal kp response with M1 latency removed. A slow first-order rise ≈ the filter is live in MIT mode.

Note  If live, this is probably the physical origin of hip_roll's "most ring, lowest ω" act_lag fit — model it as an explicit first-order command filter on hip_roll rather than through act_lag.

feeds → hip_roll command-path model (phase 7)

Phase 3 — Torque ceiling & speed envelope ~2 h

The dumps contradict the cfg: RS01 limit_cur=23 A × Kt 0.562 = 12.9 Nm with field weakening off (I_FW_MAX=0), vs saturation_effort=17 in sim (knee joint-side: ~17.6 vs 23.2 modeled). The 08-14 "no limit binding" check covered limit_torque, not the current clamp. EL05 is fine (11 A × 0.68 = 7.5 ≥ 6).

M3.1 — Stall ceiling (RS01)

Procedure  Lock the output through a lever on a load cell (or hang calibrated weights). Ramp τff 0 → 17 Nm over ~5 s. Record where measured torque plateaus. Keep bursts <3 s, rest 60 s between; watch motorTemp.

Accept  plateau within 10% of either 12.9 (current-clamped) or 17 (command-clamped) — ambiguous results mean the load cell setup is bad, redo.

feeds → saturation_effort (hip_pitch, knee ×30/22)

M3.2 — Torque–speed corner

Procedure  Max-τff spin-up of the unloaded joint; log velocity trajectory. Terminal velocity gives the true no-load corner at the real bus (~31.8 V, not the assumed 30 V); the deceleration of available accel vs speed traces τmax(v). Note where firmware limit_spd (44 RS01 / 50 EL05) cuts in — sim ignores this clamp entirely.

feeds → velocity_limit per joint; sanity-check the DC envelope shape

Phase 4 — Step-response re-sysid ~1.5 h

The act_lag prefilter (ω=21/37.9/27.6, ζ=0.41/0.80/0.58) was fitted through old-bus latency and filtered telemetry — forensics already concluded ≥2/3 of it is phantom. It currently teaches the policy to pre-compensate a plant that no longer exists.

  • Re-run the existing sysid step/chirp battery through CAN2SPI with the verified decode (same scripts as the original FRICTION_TUNE / act_lag campaign; reuse data/sysid_replay_policy_log.py infra).
  • Fit order: first subtract the measured M1 transport delay and the M2 velocity/reference filters, then fit whatever 2nd-order lag remains.
  • Decision rule: if the residual rise time is <1 control step, set act_lag_enable=False and let delay + filters carry it. Otherwise refit ω/ζ and shrink the DR bands (±18/±30% were sized for uncertainty we no longer have).

feeds → act_lag_* in cfg §11, dr_act_lag_* in §12a

Phase 5 — Friction & armature ~2 h

The cfg calls the current frictions "placeholders pending bench data"; the sysid centrals were fitted through corrupted telemetry. The 0.5–2× DR likely covers reality — today we move the centers, not the bands.

  • Breakaway (static): slow τff ramp from zero until motion; 10 trials per joint, both directions. Median → friction.
  • Coast-down (viscous + Coulomb): spin to ~15 rad/s, cut torque, log decay. Fit τ = −(C·sign(v) + b·v) → dynamic_friction, viscous_friction.
  • Knee: run belt-off (motor free) then belt-on to separate motor friction from belt drag; the difference belongs in the belt model, not the motor numbers.
  • Armature: from τff step vs initial acceleration on the free motor (I = τ/α with friction subtracted). Check hip_pitch's combined 8.4e-3 approximation against measurement.

feeds → friction / dynamic_friction / viscous_friction / armature centrals in both actuator factories

Phase 6 — Mass, balance point, init_h ~1 h

  • Weigh the assembled robot (battery + cables as flown); compare against USD total (_nominal_total_mass). If off >5%, recenter dr_mass_mult rather than widening it.
  • Static balance: stand the robot in the default pose on a straightedge / force plate; find the actual sagittal balance point vs the model's. The known +0.075 static bias exceeds dr_proj_grav_bias_max=0.03 — first try to remove it (IMU mounting re-zero, encoder mechanical zeros) and only widen the DR band for whatever residual survives. Prefer fixing hardware over widening sim.
  • init_h: the one obs channel off-distribution (−1.07σ). Measure true base height in the hardware launch pose and either fix the deployed value or widen the sim init distribution to cover it.

Implementation notes for the kd-EMA: the filter state lives per-joint inside BeltKneeDCMotor.compute() (and the plain DCMotor path for hip_roll), advanced at the identified firmware rate, and the knee's belt-drag term −kd·c·q̇_hp must use the same filtered hip velocity the firmware sees — filtering only the knee's own velocity would model half the effect. Phase 8 — Replica validation gate ~1.5 h

Cheapest possible test of the whole day's work — no training run needed.

  • Replay the calm logs and the 26 fall logs through the updated replica (data/sysid_replay_policy_log.py). Teacher-forcing RMSE must improve on calm logs vs the old model (baseline: knee TF 0.0581).
  • Run the hw-matched sim launch with the updated plant. Pass: it tips forward pitch-first in <0.5 s, onset near 0.16 s, like all 26 hardware runs. Fail: it still balances → the gap is elsewhere; return to hypothesis hunting (the "un-caught launch transient" question is still open) instead of training.
Gate G1 Fall reproduced in replica → proceed to Phase 9. Not reproduced → stop; do not spend a training cycle on an unvalidated plant.

Phase 9 — Retrain launch ~30 min + run

  • Fresh run, not a resume (actuator model changed; checkpoints are incompatible anyway).
  • Hyperparameter trap 1: a fresh run reads cfg defaults — re-check entropy coefficient explicitly (the G-series regression came from resume silently reverting to 3× the parent's entropy).
  • Hyperparameter trap 2: desired_kl=0.003 pins the adaptive LR at rsl_rl's 1e-5 floor. Decide the KL target consciously for a from-scratch run.
  • First-iteration sanity (from the cfg dev notes): actuators["hip_roll"].stiffness.std() > 0 after one reset (per-env DR write path alive); act_lag banner matches intent; diagnostics/clip_fraction and raw_action_p99_abs not exploding.
  • Watch in the first 200 iters: knee_sat_ema_max riding its fence, idle_toe_z_p10 vs swing_clearance_zero_m=0.075 (re-calibrate per the cfg rule if stance height shifts), and the DR–eplen correlations for the new delay/filter axes.

Before the new policy ever touches hardware:

  • Obs normalizer: confirm policy.py loads the rsl_rl normalizer keys (the pre-08-06 raw-obs bug must stay dead) — diff exported keys against the checkpoint.
  • Bridge LPF aliasing item from the 08-14 audit: resolve or consciously accept before flight.
  • If M2.2 changed spd_filt_gain in firmware: verify all four RS01s carry the new value (re-dump) and that the sim trained against the matching filter.
  • Hardware re-entry protocol: hang test (gains/direction sanity) → supported stand → free stand, full telemetry logging from the first trial.
